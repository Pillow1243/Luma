# Luma — Android platform (Capacitor)

The repository ships **two** Android build paths.

## 1. Capacitor (standard Android Studio / Gradle flow)

`capacitor.config.ts` points the native WebView at the live Vercel deployment
(`server.url`), so the app always runs the newest UI without a store release.

```bash
npm install
npm run build
npx cap add android      # regenerates android/ (not committed — see below)
npx cap sync android
npx cap open android     # opens Android Studio, then Run ▶
```

> `android/` is intentionally **not committed**. It is generated by
> `npx cap add android` and contains only Gradle wrappers; keeping it out of Git
> is what prevents Vercel from trying to build an Android project (the cause of
> the earlier "missing deployable file set" error).

Point the shell at another host (emulator / LAN dev server):

```bash
LUMA_SERVER_URL=http://10.0.2.2:5173 npx cap sync android
```

## 2. Gradle-free release APK (what `npm run apk` builds)

`scripts/build-apk.mjs` assembles a signed, zipaligned release APK using only
`aapt2`, `d8`, `ecj` and `apksigner` — no Gradle, no Google Maven, no AndroidX.

```bash
npm run apk            # → release/luma-1.0.0.apk  (release-signed)
npm run apk -- --debug # → release/luma-1.0.0-debug.apk
```

The native shell (`mobile/apk-shell/`) is a dependency-free `Activity` that:

- loads the live Vercel URL, and transparently falls back to the web bundle
  **embedded in the APK** (`assets/public`) when the network is unavailable;
- paints the Luma splash and edge-to-edge ink system bars;
- applies notch / gesture-bar safe insets;
- bridges media-capture permission requests and hands external links to the OS;
- routes the hardware back button through WebView history.

### Toolchain

| Tool | Source | Override |
| --- | --- | --- |
| `aapt2` | `node_modules/aaptjs3` | `$AAPT2` |
| `android.jar` | `mobile/apk-shell/libs` | `$ANDROID_JAR` |
| `d8.jar` | `mobile/apk-shell/libs` | `$D8_JAR` |
| `ecj-3.45.0.jar` | `mobile/apk-shell/libs` | `$ECJ_JAR` |
| `apksigner.jar` | `mobile/apk-shell/libs` | `$APKSIGNER_JAR` |
| `java` | `.jdk/` (`npm run jdk`), `$JAVA_HOME`, `PATH` | `$JAVA_HOME` |

`npm run jdk` provisions a Temurin JDK from PyPI (`jdk4py`) for environments
where Adoptium's CDN is unreachable.

### Signing

The release key lives at `mobile/keystore/luma-release.keystore`
(alias `luma`). Override the password with `LUMA_KEYSTORE_PASS` /
`LUMA_KEY_ALIAS`. Regenerate with `npm run keystore -- --force`.

> Keep that file and its password safe: Android only accepts in-place upgrades
> from APKs signed with the same key. **Back it up.**
